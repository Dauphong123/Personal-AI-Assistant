## Verified findings
- Windows: `HTTPServer.allow_reuse_address` (SO_REUSEADDR) lets a second process bind the same port silently; `backend.server.WebServer` turns it off (`tests/test_backend_server.py::LoopbackTests`). A refused HTTP body must be drained or the 413 is lost to a connection reset (`Handler._discard`).
- Windows: closing a socket with an unread request body resets the connection, so the client gets `ConnectionAbortedError` instead of the 401/403; `backend/server.py` drains refused POST bodies (`tests/test_backend_server.py::SecurityTests::test_refused_post_is_answered_not_reset`, was 1-in-150 flaky). [verified 2026-11-17]
- `faster_whisper.audio.decode_audio` (faster-whisper 1.2.1) fails with PyAV 19.0.2 (`open() got an unexpected keyword argument 'metadata_errors'`); `backend.voice.decode_recording` uses PyAV directly (`tests/test_backend_voice.py::RealDecodeTests`). The keyboard voice mode is unaffected (passes raw samples). [verified 2026-11-17]
- Headless Chrome `--virtual-time-budget` / `--dump-dom` never finish on the web chat (an open EventSource keeps the network busy); drive it over the DevTools protocol instead (Node's built-in `WebSocket`). [verified 2026-11-17]
- Long-term memory saved episodes but no facts (DB had 4 episodes, 0 facts): the extractor prompt listed only preferences/project/environment, so qwen3:8b skipped "my name is Dat", and `is_trivial_turn` (< 3 words) dropped "I'm Dat" before the model. Fixed in F021 step 0 (`tests/test_memory.py::TrivialTurnTests`, `ExtractionPromptTests`). [verified 2026-11-17]
- qwen3:8b extraction at the chat default temperature (~0.6) varied between runs and once stored "The user's OpenAI key is sk-..." despite the prompt; temperature 0 plus the `looks_secret` filter fixed both (scratchpad eval 13/13). bge-small blurs short facts: "The user uses Vim" is closer to "The user is a student" (0.23) than to "The user's preferred code editor is VS Code" (0.36); with the same subject wording ("The user's code editor is ...") they are 0.09 apart. Vietnamese questions score 0.39-0.59 against English facts. [verified 2026-11-17, measured with bge-small-en-v1.5]
- Memory retrieval eval (`tests/test_memory_eval.py`): 15/30 -> profile 26/30 -> (35 cases) hybrid 32/35 -> follow-up 33/35 -> (40 cases, 5 held-out Vietnamese) bge 36/40, multilingual-e5-small 40/40 at recall cutoff 0.20 (0.3 extra facts a question). e5 distances: paraphrase <= 0.034, same subject 0.05-0.14, different subject >= 0.14, relevant question 0.13-0.24, unrelated 0.20-0.29. A known-fact cutoff of 0.24 pulled unrelated facts into the extractor prompt and qwen3:8b then missed the new fact; 0.18 fixed it. [verified 2026-11-17]
- Headless Chrome with `--use-fake-ui-for-media-stream --use-fake-device-for-media-stream --use-file-for-fake-audio-capture=<wav>` (looped 1.2 s tone bursts) drives the web hands-free loop end to end: utterances split, prompts queued and sent in order, "stop listening" ends it (scratchpad script, fake STT and model). [verified 2026-11-17]
- `ctypes.WinDLL("user32").GetAsyncKeyState(0xA3)` reads Right Ctrl from the venv without extra packages (`voice.build_key`). [verified 2026-11-17]
- Web Talk/Hands-free buttons were missing because web voice was opt-in (`--voice`): without it the handshake reports `voice.transcribe=false` (`backend/server.py` `describe`) and `webui/src/main.ts` `setUpVoice` hides them. Now on by default when the packages are installed, `--no-voice` to turn off (`tests/test_backend_main.py::MainTests`). [verified 2026-11-18, real handshake]
- Headless Chrome over DevTools: `navigator.clipboard` fails with NotAllowedError until `Emulation.setFocusEmulationEnabled` and `Browser.grantPermissions` (`clipboardReadWrite`, with the page origin) are sent; with them, the web chat's Copy buttons can be checked. The F022 tone-burst fake microphone also drives the F023 voice meter (Listening → Hearing you → Transcribing). [verified 2026-11-18, scratchpad scripts]
- Ollama 0.40.16 / qwen3:8b on this machine: 2.36 of 6.6 GB on the GPU; 5.4-6.2 tok/s out, ~460 tok/s prompt; `qwen3:4b` 14.2 tok/s plain but thinks with tools; only one model loaded at a time (loading 4b unloaded 8b; reload ~8 s); runner flags `-np 1 --context-shift --keep 4` (server.log). [verified 2026-11-18, scratchpad probes]
- Ollama's qwen3 template renders all system messages at the top (`.System`), so a mid-conversation system message changes the prompt start (2,247 → 2,249 tokens, full re-read). Prompt reuse: identical prompt 0.2 s, changed tail 1.6-2.8 s, changed start 4.8 s (2.2k tokens). [verified 2026-11-18, `/api/show` + `/api/chat` probes]
- Cancelling an async Ollama request (closing the HTTP connection) stops generation: the next call started in 1.0-1.7 s instead of waiting ~30 s. ChatOllama's async client is bound to the first event loop; a closed loop breaks later calls ("Event loop is closed"), and a loop left open logs "Cancelling an overlapped future failed" at exit on Windows (`tests/test_graph_speed.py::CancellableExtractionTests`). [verified 2026-11-18]
- `test_transcribe_size_limits` was flaky (~1 in 8-16 suite runs): it uploads `MAX_AUDIO`+1 (4 MB) but the server drained only `DISCARD_LIMIT` (1 MB) before the 413 and close; Windows resets a socket closed with unread data (probe: 25/300 lost). `DISCARD_LIMIT = 2 * MAX_AUDIO` → 0/300 (`tests/test_backend_voice.py::test_a_recording_just_over_the_limit_is_drained_so_the_413_arrives`). Passes alone (0/40); only fails under suite load. [verified 2026-11-18, scratchpad probe]
- Pyright's dataclass transform ignores pydantic `Field(None, ...)` positional defaults ("argument missing" at every call); `Field(default=None, ...)` fixes it with the same behavior (`memories/extractor.py`). [verified 2026-11-18]
