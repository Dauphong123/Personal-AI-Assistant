# Web chat backend (`backend/`)

`python -m backend [--host H] [--port N] [--allow-remote] [--max-turns N] [--no-voice] [--frontend-origin ORIGIN ...] [--serve-frontend]`: the agent's HTTP API over the same graph as `main.py` (does not touch `main.py`/`ChatLoop`). API only by default: the frontend (`frontend/`, see `frontend/CLAUDE.md`) runs on its own server and calls this API cross-origin. Startup prints the frontend link `<origin>/?api=<this API>&token=<token>` and the matching `npm --prefix frontend start [-- --api ... --port ...]` (`frontend_url`, `frontend_command`; `FRONTEND_SERVER_PORT`/`FRONTEND_SERVER_API` must equal `frontend/scripts/serve.ts` `DEFAULT_PORT`/`DEFAULT_API`, a test checks). `--serve-frontend` also serves `frontend/dist` on this origin (then it refuses to start until the frontend is built).

- **Handshake** (`POST /api/handshake {protocol}`): the page's first call. `server.PROTOCOL` must equal `frontend/src/types.ts` `PROTOCOL` (a test checks); bump both on an incompatible API change. Mismatch → 409 telling the user to rebuild. Answer: `{protocol, server, features: {sessions, notices, voice: {transcribe, speak}}, limits}` from `WebServer.describe()`; the page shows voice controls only when offered.
- `session.py`: `ChatSession` = one conversation (own `id`, LangGraph `thread_id`, title). Runs `turns.run_turn` on a worker thread and records an id-numbered event log (`user`, `notice`, `waiting`, `token`, `approval`, `done`, `cancelled`, `error`, `reset`). Each `approval` event carries a `request` id; `approve(allow, request)` answers only that request (`POST .../approve {allow, request}`: 400 without it, 409 when another request or none waits), so a stale click or a second tab cannot approve a later tool call (protocol 2). `events_after(id)` lets a client resume. One turn at a time per session. Title = first message unless renamed. `info()` → `{id, title, state: idle|waiting|running|approval, created, last_event}`. Each turn runs inside `jobs.job_owner(session id)`.
- **Job notices**: `JobManager` stamps each job with `jobs.JOB_OWNER` (a contextvar; langgraph copies the context into node threads, so the `terminal` tool sees the session). `__main__.connect_jobs` sets `JOBS.on_finish = SessionManager.job_finished`, which calls `ChatSession.notify(finished_notice(job), summary)`: a `notice` turn (`run_turn(notice=True)`, so memory skips it) that runs now or right after the current turn; `stop` keeps queued notices; a deleted session's notices are dropped.
- `sessions.py`: `SessionManager` holds sessions (max 50, in memory: a restart forgets them) and one shared semaphore: at most `--max-turns` (default 1) turns run at once; a session that must wait emits `waiting` and can be stopped while waiting. `delete` refused while busy.
- `voice.py` (on by default when the voice packages are installed, `None` when none are; `--no-voice` turns it off): `WebVoice` = push-to-talk for the browser. `POST /api/voice/transcribe` (raw `audio/*` body, 4 MB cap) → PyAV decode to 16 kHz → `voice.stt.FasterWhisperTranscriber`; `?dictate=1` adds `{prompt, hands_free, answer}` (`backend.voice.dictation`: cleaned prompt, "on"/"off" for hands-free phrases, approval answer y/n/stop); without it the answer stays `{text}`. `POST /api/voice/speak {text}` → `voice.text.clean_for_speech` → Piper (Vietnamese voice for Vietnamese text) → `audio/wav` (204 if nothing speakable). Models load on first use; 503 when not enabled. Decoding uses PyAV directly: `faster_whisper.decode_audio` (1.2.1) breaks on PyAV 19. No wake word or speaker verification on the web path.
- `server.py`: stdlib `ThreadingHTTPServer`. Routes listed in its docstring. SSE ends with `{"type":"gone"}` when the session is deleted. Security (keep when editing): loopback only unless `allow_remote`; token (`X-Token` / `Bearer`; `?token=` only for `/events`) via `hmac.compare_digest`; Host must be ours; Origin must be ours or a listed frontend origin (`frontend_origins`, checked by `parse_origin`: scheme + host + port only); for a listed origin every answer (JSON, SSE, 204) carries `Access-Control-Allow-Origin: <origin>` + `Vary: Origin`, and `OPTIONS /api/...` preflights get 204 (methods GET/POST, headers Content-Type/X-Token/Authorization), any other origin 403; `static_dir=None` (default of `make_server`) = API only, other paths 404 with a hint; JSON-only POST (64 KB) except the audio upload; a refused POST's body is drained first (else Windows resets the connection and the client never sees the 4xx); static files only from the build dir, known extensions, no hidden names / `..` / backslashes, resolved path must stay inside; CSP forbids inline script/style (allows `media-src blob:` for spoken answers); no access log (URLs carry the token); `allow_reuse_address = False`. A handler that raises answers 500 `Internal server error` and is logged (path only); `Handler.timeout` 30 s (> SSE keepalive 10 s); `GET /api/health` needs no token; refused bodies drained up to `DISCARD_LIMIT` = 2 x `MAX_AUDIO`.
- `__main__.py`: SIGTERM / Ctrl+Break stop like Ctrl+C (`install_stop_signals`), so jobs are killed and memory saved; refuses a non-loopback host, bad `--max-turns`, a bad `--frontend-origin` or (with `--serve-frontend`) a missing build before loading models; heavy imports in `build_app()` / `build_voice()` / `connect_jobs()` / `cleanup()` so tests patch them.

Tests (`tests/test_backend_*.py`, `tests/test_job_owner.py`) stub `dependency` (`tests/stubs.py`) and inject a fake `run` and fake voice engines; no Ollama, DB or models (PyAV decoding is real). Known gaps: sessions not persisted, tool output streams into the answer text.
